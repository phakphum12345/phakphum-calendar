# User journeys and capability boundaries

Personal journey: open app, use Personal mode, configure shifts/rules, import or enter roster, review validation, confirm assignments, view calendar/history/statement and use local AI help if desired.

Organization journey: sign in, join/create organization, receive role, use tenant-scoped roster/rules and review audit history.

Hybrid journey: select sources, review precedence, inspect resolved source per assignment and resolve ambiguity explicitly.

UI distinguishes available-local, requires-sign-in, requires-org-role, requires-consent, requires-provider, unavailable and planned. A visible control is not proof of a working capability.
