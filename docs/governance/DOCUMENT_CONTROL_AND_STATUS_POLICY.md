# Document control and status policy

Each domain has one canonical requirements/design document, implementation map, acceptance set and evidence/status source. Historical documents remain available and link to canonical current documents.

Feature changes update product requirement/user journey, architecture/data contracts, implementation/dependency map, acceptance/traceability and the master index.

Statuses: PLANNED, IN PROGRESS, PARTIAL, PASS, BLOCKED, FAIL and UNKNOWN. PASS requires current evidence for the stated scope and exact revision.

New canonical work belongs in its domain folder. Avoid new root-level documents when a canonical nested document exists. Keep legacy root docs until reviewed; do not bulk-move/delete without a dedicated migration plan.
